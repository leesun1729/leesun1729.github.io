# 维护指南

这份文档写给「以后回来改站点的自己」。目标：不需要重新读一遍源码，就能改对。

---

## 0. 先记住三条铁律

1. **改了源码必须重新构建**。`npm run preview` 只是把 `dist/` 静态伺服起来，它不会重新生成页面。
   ```
   npm run build && npm run preview
   ```
   写内容时用 `npm run dev`（热更新，改完立刻能看到）。

2. **别双击 `dist/index.html` 看效果**。构建产物里资源是绝对路径（`/_astro/xxx.css`），
   `file://` 打开会变成没样式的裸 HTML。必须走 HTTP。

3. **不要手工改这两个文件**：
   - `src/styles/fonts.css` —— 由 `scripts/build-fonts.py` 生成，手改会在下次重建时丢失。
   - `dist/` —— 构建产物，随时会被覆盖。

## 1. 站点结构速查

```
src/
├── content/              ← 内容都在这里，日常只动这个目录
│   ├── articles/         ← 文章（Markdown，一篇一个文件）
│   └── projects/         ← 项目（一个项目一个目录，含 zh.md / en.md）
├── pages/                ← 页面模板（改版式才动）
│   ├── index.astro          首页
│   ├── articles/            文章列表 + [slug].astro 文章详情
│   ├── projects/            项目列表
│   ├── about/               关于
│   ├── ranking/             榜单
│   ├── links/               友链
│   └── en/                  以上页面的英文版
├── layouts/              ← 页面骨架（ArticleLayout / ProjectLayout / BaseLayout）
├── components/           ← 可复用组件（PostCard / Header / Footer / ThemeToggle…）
├── styles/global.css     ← 全站唯一样式来源（颜色、字阶、间距、卡片）
├── lib/site.ts           ← 站点元信息 + 顶部导航
└── content.config.ts     ← 内容字段的校验规则（改字段名要同步改这里）
```

**关键概念**：`src/content/` 里文件的 **frontmatter 字段受 schema 校验**。
写错字段名不会静默失败，而是**构建直接报错**——这是好事，能立刻发现拼错。

## 2. 怎么加一篇文章

### 2.1 新建文件

文章是**双语的**：一篇文章一个目录，里面放 `zh.md` 和 `en.md`。目录名就是网址：

```
src/content/articles/my-first-post/
├── zh.md    →   /articles/my-first-post/
└── en.md    →   /en/articles/my-first-post/
```

**最省事的做法**：直接复制模版
```bash
cp -r src/content/articles/_template src/content/articles/my-first-post
```
模版里已经写好了全部字段说明和常用写法示例（标题、代码块、折叠块、表格、公式）。
以 `_` 开头的目录会被 Astro 忽略，所以模版本身不会变成页面。

> 目录名建议用英文小写加连字符。中文也能用，但中文会进 URL，
> 分享出去会变成一长串百分号编码。

> **只写中文也可以**：那就只放 `zh.md`，英文站不会列出这篇。
> 但两个都写的话，页面右上角的语言切换能正确跳转到对应语言版本。

### 2.2 写 frontmatter

```markdown
---
title: '文章标题'
date: 2026-10-16T20:00:00+08:00
tags: ['标签A', '标签B']
summary: '一句话摘要，会显示在列表卡片上（超过三行会被截断）'
draft: false
---

正文从这里开始……
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 文章标题 |
| `date` | ✅ | 发布日期，决定排序（新的在前）和显示 |
| `tags` | 否 | 数组，留空写 `[]` 或直接不写 |
| `summary` | 否 | 摘要，显示在列表卡片上；不写则卡片不显示摘要行 |
| `updated` | 否 | 修订日期，写了会在文章页左侧显示「修订」 |
| `draft` | 否 | `true` 则该文**不出现**在任何列表和构建产物里 |

**注意日期格式**：`2026-10-16T20:00:00+08:00` 是标准写法（带时区）。
只写 `2026-10-16` 也可以。

### 2.3 写正文

普通 Markdown。这个站点对中文排版做了处理，你**不需要手动做**这些事：

- 段落**首行缩进 2 字符** —— 自动的，别自己打空格。
- 中英文之间**自动加间距** —— 自动的（`src/scripts/han.ts`）。
- 标点避头尾、行内标点压缩 —— 自动的。

**代码块**用三个反引号，语法高亮是灰阶的（不是彩色），和全站风格一致：

````markdown
```cpp
int main() { return 0; }
```
````

支持 `<details>` 折叠（现有文章里用了 22 处）：

```html
<details>
<summary>点开看更多</summary>

折叠内容

</details>
```

### 2.4 检查

```bash
npm run dev      # 打开 http://localhost:4321/articles/ 看效果
```

## 3. 怎么加一个项目

项目是**双语的**：一个项目一个目录，里面放 `zh.md` 和 `en.md`。

```
src/content/projects/
└── my-app/
    ├── zh.md     ← 中文
    └── en.md     ← 英文
```

网址是 `/projects/my-app/`（用目录名）。

**最省事的做法**：复制模版
```bash
cp -r src/content/projects/_template src/content/projects/my-app
```

⚠️ **项目详情页需要手动加路由**（文章不用）：
```bash
cp src/pages/projects/paste.astro src/pages/projects/my-app.astro
cp src/pages/en/projects/paste.astro src/pages/en/projects/my-app.astro
# 然后把这两个新文件里的 'paste' 改成 'my-app'
```

frontmatter：

```markdown
---
title: 'MyApp'
tagline: '一句话介绍，显示在卡片上'
date: 2026-10-16
stack: ['SwiftUI', 'macOS']
status: '已发布'
links:
  repo: 'https://github.com/leesun1729/MyApp'
  release: 'https://github.com/leesun1729/MyApp/releases/latest'
  demo: 'https://example.com'
featured: true
order: 1
---

正文介绍……
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 项目名 |
| `tagline` | ✅ | 一句话简介，卡片上显示 |
| `date` | ✅ | 日期 |
| `stack` | 否 | 技术栈数组，显示为标签 |
| `status` | 否 | 如「已发布」「开发中」 |
| `links.repo` | 否 | 源码仓库地址 |
| `links.release` | 否 | 下载地址 |
| `links.demo` | 否 | 在线演示地址 |
| `featured` | 否 | 是否精选 |
| `order` | 否 | 排序，**数字小的在前**（默认 99） |

`links` 里的三个链接**只写你要显示的那些**，没写的不显示（不会出现空链接）。

## 4. 怎么增加「足迹」

足迹在 `src/pages/about/index.astro` 和 `src/pages/en/about/index.astro`（两个语言各一份）。

**现状**：地图是一块**虚线占位框**，因为暂时不想引入地图服务（地图瓦片在国内加载慢，且会引入外部依赖）。

有两条路：

### 路线 A：先填文字（最省事，推荐先做这个）

在 `src/pages/about/index.astro` 里找到：

```astro
<p>去过的地方还不多，先在这里留一块地方。</p>
```

改成你想写的，比如：

```astro
<p>住过汕头、深圳，去过北京、上海、成都。</p>
```

想加城市列表，就用已有的 `.legend` 结构（`居住` / `旅行` 两个标记已经有了）：

```astro
<ul class="legend">
  <li><span class="marker marker--home" aria-hidden="true"></span>汕头 · 深圳</li>
  <li><span class="marker marker--trip" aria-hidden="true"></span>北京 · 上海 · 成都</li>
</ul>
```

### 路线 B：换成真地图

把 `<div class="map">…</div>` 整块替换成静态图片（自己截图一张地图，别引第三方 JS）：

```astro
<img class="map" src="/map.png" alt="足迹地图" />
```

把 `map.png` 放进 `public/` 目录（`public/` 里的文件会原样复制到网站根目录）。

> **别用** Leaflet / Mapbox 之类的 JS 地图：会引入外部请求，大陆访问可能很慢或直接失败，
> 而且和这个站「零外部依赖」的设计相悖。

## 5. 怎么填「动漫」

同样是 `src/pages/about/index.astro`（和英文版）。现在是 6 个虚线占位格。

找到：

```astro
<ul class="anime-grid" aria-label="动漫占位，待补充">
  {
    animeSlots.map(() => (
      <li class="anime-slot">
        <span aria-hidden="true">＋</span>
      </li>
    ))
  }
</ul>
```

**最省事的改法** —— 把上面的数据数组（文件顶部）改成真实内容：

```astro
const animeSlots = [
  '进击的巨人（2013）· 第一季最好看',
  '灵笼（2019）· 国漫科幻天花板',
  '雾山五行（2020）· 打斗分镜极强',
];
```

然后把 `<ul>` 里改成渲染文字：

```astro
<ul class="anime-grid">
  {animeSlots.map((t) => <li class="anime-slot">{t}</li>)}
</ul>
```

不够用就加数组项，用不到就删。

## 6. 改导航菜单

在 `src/lib/site.ts` 的 `NAV`：

```ts
export const NAV: Record<Lang, { href: string; label: string }[]> = {
  zh: [
    { href: '/', label: '首页' },
    { href: '/articles/', label: '文章' },
    { href: '/projects/', label: '项目' },
    { href: '/ranking/', label: '榜单' },
    { href: '/about/', label: '关于' },
    { href: '/links/', label: '友链' },
  ],
  en: [
    { href: '/en/', label: 'Home' },
    { href: '/en/articles/', label: 'Articles' },
    { href: '/en/projects/', label: 'Projects' },
    { href: '/en/ranking/', label: 'Ranking' },
    { href: '/en/about/', label: 'About' },
  ],
};
```

数组顺序 = 页面上的顺序。**加一项就在这里加**，Header 会自动渲染。

> 注意：`zh` 有「友链」，`en` 没有（英文版没有友链页）。这是有意的。

## 8. 首页头像与社交图标

首页 hero 右侧是头像，用的是 `public/favicons/favicon-512x512.png`。

**换头像**：把新图放进 `public/`，然后改 `src/pages/index.astro`（和英文版）里的 src：
```astro
<img class="hero-portrait" src="/avatars/me.jpg" alt="leesun" width="220" height="260" />
```
CSS 会把它缩到 220×260。建议原图先压到 440×520 以内，省流量。

**加/删社交图标**：hero 里的 `.social-row` 是一排内联 SVG（用 `currentColor`，
所以自动跟随深浅色）。加一个就在 `src/pages/index.astro` 里加一条 `<li>`：
```astro
<li>
  <a href="https://your-link" aria-label="平台名">
    <svg viewBox="0 0 16 16" fill="currentColor" aria-hidden="true"><path d="…"/></svg>
  </a>
</li>
```
图标从 [Simple Icons](https://simpleicons.org/) 拿 `path` 的 `d` 值即可。

**站点图标**（浏览器标签页、手机桌面图标）在 `public/favicons/`，
由 `src/layouts/BaseLayout.astro` 的 `<head>` 引用。要换就整套替换同名文件。

## 8.1 页脚

页脚在 `src/components/Footer.astro`，内容是从 `SITE` 和构建时间算出来的：
- `已运行 N 天` —— 从 `SITE.startYear`（2024）算起，**每次构建时重新计算**，
  所以重新部署后数字会自己变大
- `© 年份 leesun，保留所有权利`
- 站点地图链接

要改措辞就改这个文件里的 `L` 对象（中英各一份）。

## 9. 改颜色和字号

全站颜色、字阶、间距**只在 `src/styles/global.css` 顶部的 `:root` 里**：

```css
--bg: #ffffff;          /* 页面底色 */
--fg: #000000;          /* 标题 */
--fg-body: #171717;     /* 正文 */
--muted: #525252;       /* 次要文字 */
--meta: #262626;        /* meta 行 */
--line: #d4d4d4;        /* 虚线边框（永不作为文字色） */
--line-strong: #a3a3a3; /* 次级分隔线 */
```

深色模式的值在下面三个块里（系统跟随 / 强制深色 / 强制浅色），**改浅色要记得同步改深色**。

> ⚠️ 这个站点是**刻意纯灰阶**的（参考 diygod.cc）。加彩色会破坏整体语言。
> 如果你确实要加，改 `--fg` 之类的令牌即可，不要去各个页面里写死颜色。

## 10. 改完怎么发布

```bash
npm run build          # 生成 dist/
npm run check:fonts    # 可选：检查字体切片覆盖（新增大量汉字后建议跑）
git add -A
git commit -m "说明这次改了什么"
git push
```

推送到 GitHub 后，GitHub Actions 会自动部署（`.github/workflows/`）。
等 1–2 分钟刷新 https://leesun1729.github.io/ 就能看到。

## 11. 出问题时

| 症状 | 原因 |
|---|---|
| 构建报 `does not match collection schema` | frontmatter 字段名拼错或类型不对（比如 `tags` 写成了字符串而不是数组） |
| 页面 404 | 文件名/目录名和 URL 对不上；或者 `draft: true` |
| 改了样式没变化 | 没重新 `build`；或改的是 `dist/` 里的文件（会被覆盖） |
| 字体变成默认字体 | 新增了大量汉字，需重建字体切片（见下） |
| 列表里没有新文章 | `draft: true`，或 `date` 写成了未来时间且被过滤 |

### 字体切片是什么

站点自托管字体（Google Fonts 在大陆被 DNS 污染，不能用），并按 **unicode-range 切成两片**：

- **切片 A**（约 137 KB）：站点实际用到的字，**每页必载**。
- **切片 B**（约 565 KB）：其余常用汉字，**只在页面出现生僻字时才加载**。

正常情况切片 B 永远不会被下载。但如果你**新增了很多字**（比如加了一篇满是生僻字的文章），
可能触发切片 B。检查：

```bash
npm run build && npm run check:fonts
```

输出 `PASS` 就没事；输出 `FAIL` 会列出缺哪些字，按提示重建：

```bash
PYTHONPATH=.pylibs .dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3 scripts/build-fonts.py
```

（这条命令需要 `.pylibs` 环境。如果报错，说明 Python 依赖没装好，见 `scripts/build-fonts.py` 顶部注释。）

## 12. 常用命令速查

```bash
npm run dev            # 开发服务器，热更新，http://localhost:4321
npm run build          # 构建到 dist/
npm run preview        # 预览构建产物，http://localhost:4327
npm run check:fonts    # 检查字体切片覆盖（需先 build）

# 如果 127.0.0.1 打不开（服务只绑了 IPv6）
npx astro dev --host
npx astro preview --host
```
